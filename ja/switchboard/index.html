課題

上限は
作業より先に尽きる

長いセッションでは、作業の途中でアカウントの使用量の上限に達することがあります。すると、サインアウトして別のアカウントを探し、サインインし直す間、作業が止まってしまいます。

Switchboard は 作業 を止めません。ローテーションをオンにすると、次のリクエストは同じプールの別のアカウントに移り、セッションは開いたままです。

SWITCHBOARD の中身

アカウントをひと目で確認

実際の Switchboard の画面です。アカウントは合成したデモ用のものです。

ローカルの作業環境

アカウントの切り替え作業を減らす
状況をひと目で把握

01 / アカウント

今の状態から始める

現在の CLI アカウントを明示的に取り込む、公式 CLI でサインインする、または Claude Swap のプロファイルをインポートできます。Switchboard に取り込むものはご自身で選べます。

02 / 境界

仕事は仕事、個人は個人

仕事用や個人用などのプールにアカウントをまとめます。ルーティングは同じプロバイダーかつ同じプール内にとどまります。

03 / 使用量

残りの上限を確認

報告されたクォータの期間、リセット時刻、各確認の経過時間を確認できます。未対応または不明な使用量は、はっきり不明と表示されます。

04 / 切り替え

次のリクエストを変える

マネージドルートを選ぶか、クォータを考慮したローテーションを有効にします。処理中のレスポンスは、開始時のアイデンティティのまま続きます。

05 / ローカル保存

認証情報を手元のマシンに保管

保存されるシークレットには macOS キーチェーンまたは Windows DPAPI を使います。分離された CLI の起動では、公式クライアントが必要とするアクセストークンのローカルコピーが作成されます。

06 / ワークフロー

ウィンドウでもターミナルでも

デスクトップアプリと CLI は同じランタイムを共有します。マネージドセッションでは、アプリまたはswitchboard serveを起動したままにしてください。

エージェント向け · 0.4 の新機能

エージェントが自分の
上限を確認できます

Switchboard にはswitchboard mcpが含まれています。これはローカルの MCP サーバーです。Claude Code、Codex、その他の MCP クライアントは、残っている使用量を読み取り、次のリクエストを別のアカウントに移せます。認証情報を受け取る、または返すツールはありません。

01 / 使用量

残りを読み取る

各アカウントと各期間の残りクォータを、リセット時刻と各確認の経過時間とともに取得できます。使用量が不明な場合は、ゼロではなく不明として報告されます。

02 / 切り替え

上限に達する前に切り替える

エージェントは、同じプロバイダーかつ同じプール内で、セッションの次のリクエストに使うアカウントを選べます。Mac 上のすべてのセッションに対する Claude Code のログインを変更するには、明示的なglobalフラグが必要です。

03 / プロジェクトルール

任意のプロジェクトルール

ご希望であれば、プロジェクトフォルダーを選んだアカウントで開始できます。ルールはアプリ内に表示され、一時停止や有効期限の設定ができ、ローテーションを止めることはありません。

  1. 01

    Switchboard から起動

    アプリまたは CLI から起動したセッションでは、switchboard CLI が見つかればエージェントツールが使えます。分離されたセッションでは読み取り専用のツールのみ使えます。macOS では、アプリの「エージェント」パネルがアプリ内の CLI を次の場所にリンクします：~/.local/bin。

  2. 02

    またはエージェントを自分で接続

    claude mcp add --scope user switchboard -- switchboard mcp
    codex mcp add switchboard -- switchboard mcp

最初のセッション

アカウントを用意する
動かし方を選ぶ

  1. 01

    アカウントを追加

    現在の認証を取り込むか、公式 CLI のログインを使います。アカウントにラベルとプールを付けます。

  2. 02

    わかっていることを確認

    アカウントのアイデンティティと報告された使用量を確認します。マネージドの選択と、現在のネイティブ CLI アカウントは別々に表示されます。

  3. 03

    セッションを起動

    リクエストごとに切り替えるにはマネージドモード、1 つのアカウントに固定した直接セッションには分離モードを使います。

はじめる前に

いくつかの大切な違い

Switchboard は Claude Code や Codex の代わりになりますか？

いいえ。Switchboard はアカウントを管理し、公式の CLI を起動します。サインインとセッションのために、Claude Code または Codex を別途インストールしてください。Switchboard にはプロバイダーのサブスクリプションや API クレジットは含まれません。

現在の CLI アカウントが自動的に変わりますか？

取り込みは明示的な操作です。マネージドルートの選択は、ネイティブでの有効化とは別です。Claude のネイティブでの有効化と自動ローテーションは、オプトインの操作です。有効にする前に確認内容をご覧ください。

マネージドと分離の違いは何ですか？

マネージドセッションはローカルプロキシ経由でリクエストを送り、以降のリクエストでは選択したルートに従います。分離セッションは別のアカウントホームを使って直接接続し、その後のルート選択の影響を受けません。

Switchboard は Fabric と同じものですか？

Switchboard は、現在ご利用いただけるアカウント管理ツールです。早期プレビュー版の Fabric は、プロジェクトとそのエージェントのための拠点です。どちらも PassionCode のツールキットに含まれます。Fabric で作っているものを見る。

Switchboard はどのエージェントで使えますか？

Claude Code、Codex のほか、Hermes、Kilo Code、Cline、Goose、OpenCode など、よく使われるコーディングエージェントに対応しています。30 件すべてと接続方法を見る。

プロジェクトごとに専用のアカウントを持てますか？

はい。プロジェクトを作成し、そのフォルダー（たとえば関連する複数のリポジトリ）を追加して、使用するアカウントを選びます。それらのフォルダーから起動したセッションはそのアカウントだけを使い、自動切り替えもその範囲内にとどまります。他のプロジェクトで作業するエージェントがそれらのアカウントに切り替わることはありません。

Switchboard はデータを送信しますか？

リリースビルドは、インストール数、使用日数、接続されているアカウント数をプロバイダーと種類別に集計します。アカウント名、メールアドレス、サインイン情報、プール名、アカウントでの操作内容は送信しません。お使いのコンピューター上の PassionCode.ai ツールで共有するランダムなインストール番号により、1 人を 1 回として数えます。「概要」→「匿名の使用量カウントを共有」でオフにできます。この設定はすべての PassionCode.ai ツールに適用されます。送信される内容の詳細。

自分でソースを確認したり、ビルドしたりできますか？

はい。Switchboard は GNU AGPL-3.0 に基づくオープンソースです。AGPL がカバーしない用途には、次の窓口から商用ライセンスを利用できます：passioncode.ai/business。v0.3.1-beta.1 までのリリースは MIT ライセンスで公開されており、引き続きそのライセンスで利用できます。現在のダウンロード版（0.6.15）は AGPL の下でリリースされています。v0.4.0-beta.1 は PolyForm Noncommercial or Internal Use の下でリリースされ、そのライセンスのままです。 このリポジトリには、ビルド手順、ソース、テスト、リリースの証跡があります。
