1つのエージェントから AIネイティブな組織へ

01 / エージェントの乱立

エージェントは、
誰も把握しきれない速さで増えます

どのチームも、午後のうちにエージェントを1つ立ち上げられます。ところが1か月後に、どのエージェントが動いているのか、どのアカウントで動いているのか、いくらかかっているのか、何を変更したのか、まだ誰かが必要としているのかを答えられるチームはわずかです。単独で作られたエージェント同士は連携せず、誰も見ていないものは、静かに傷んでいきます。

MCKINSEY · 2025年11月

試す組織は多く、広げる組織は少ない

調査対象の組織の62%が、少なくともAIエージェントを試していますが、どの業務部門でも、本格展開していると答えたのは10%以下です。

GARTNER · 2025年6月

多くのプロジェクトが中止される見込み

Gartner は、コストの上昇、事業価値の不明確さ、リスク管理の不備により、エージェント型AIプロジェクトの40%超が2027年末までに中止されると予測しています。

GARTNER · 2026年4月

次の課題は乱立

Gartner の予測では、2028年までに、世界の平均的な Fortune 500 企業で15万を超えるエージェントが使われる一方、適切なエージェントガバナンスが整っていると考える組織は13%にとどまります。

FORTUNE · 2025年8月

足りないのはモデルではなく学習

マサチューセッツ工科大学の NANDA イニシアチブによるレポートは、生成AIのパイロットの大半が、損益に測定可能な効果を出せないまま停滞していると指摘しました。その原因は学習のギャップ、つまり、企業の仕事のやり方に適応しないツールだとしています。

  • McKinsey, The state of AI in 2025: Agents, innovation, and transformation（2025年11月）
  • Gartner プレスリリース、2025年6月25日
  • Gartner プレスリリース、2026年4月28日
  • Fortune、2025年8月18日、レポート The GenAI Divide: State of AI in Business 2025 について。ただし、このレポートは150件のインタビュー、350人の従業員への調査、300件の公開事例の分析に基づいており、失敗したパイロットの割合という主要な数字は、成功の定義をめぐって疑問が呈されています。測定値ではなく、1つのシグナルとして読んでください。

02 / 欠けているハーネス

問題はモデルではありません。
それを支えるものです

ハーネス（harness）とは、 モデルの周りにあって、エージェントを長く安定して動かすためのすべてを指します。作業する場所、使えるツールとアカウント、セッションをまたいで覚えておくこと、作業が通るべきチェック、そして行ったことの記録です。モデルを開発している研究機関も同じ言葉を使っており、Anthropic は長時間動くエージェントのための効果的なハーネス（2025年11月）について、OpenAI はハーネスエンジニアリング（2026年2月）について書いています。

  1. 01

    拠点

    各プロジェクトには、目的、ボード、意思決定、リリースを置く場所が1つあり、そのプロジェクトで働くすべてのエージェントが共有します。それが Fabric です。

  2. 02

    アカウント

    各エージェントは、使うべきアカウントで、上限を確認しながら動きます。それが Fabric Switchboard です。

  3. 03

    状態管理とコントロール

    すべてのエージェントサービスについて、状態、支出、アップデートを、人もエージェントも操作できる1つのウィンドウで確認できます。それが Fabric Dashboards です。

  4. 04

    メモリと証跡

    何が変わったか、何が決まったか、何に注意が必要かを、根拠とともに残します。それが Project Observatory です。

これらをつなぐのは1つのコントラクトです。オープンなFabric Agent Contractです。Fabric Agent Adapter スキルは、どのコーディングエージェントにもこれに合わせた作り方を教えるので、今日作ったエージェントは、書き直さずにファミリーへ加われます。

03 / 私たちの考え

6つの原則に
沿って作っています

  • 自分のものとして持てるエージェントあなたのマシンとあなたのアカウントで動き、コードは GNU AGPL-3.0 のもとで誰でも読めます。
  • あらゆるエージェントベンダー中立。Claude Code や Codex、そしてその先のツールの上に載るハーネスであり、それらの代わりにはなりません。
  • 必要に応じて育てる1つの仕事に1つのエージェントから始めます。次のエージェントは、計画に書いてあるからではなく、仕事が求めたときに加えます。
  • 信頼ではなく証跡すべての操作が、読める記録として残ります。完了とは、報告されたことではなく、確認されたことです。
  • 決めるのは人エージェントは仕事を準備し、確認し、進めます。何をしてよいかを決め、重要なことを承認するのは人です。
  • 常に可視化し、隠れて動かさない分析の対象は、エージェントとプロセスの成果です。人をひそかに監視することはありません。

04 / 道筋

6つの段階。
それぞれ単独で役立ちます

同じファミリーが、1人から組織全体へと育っていきます。各段階には、今日使えるものか、開発中の方向かを示しています。

  1. 01

    現在利用可能

    エージェント1つ

    コーディングエージェントが、1つの仕事のためのエージェントを、コントラクト、ダッシュボード、テストとともに作ります。

    • 個人の創業者 毎朝、アプリストアのレビューへの返信を下書きするエージェント
    • 小さなチーム マージされたプルリクエストからリリースノートを書くエージェント
    • 部門 自社のデータから週次レポートをまとめるエージェント
  2. 02

    現在利用可能

    対話する2つのエージェント

    Fabric につながったエージェントは、1つのプロジェクトのボード、メモリ、引き継ぎを共有するので、1つのエージェントが止めたところから別のエージェントが続けられます。

    • 個人の創業者 レビューエージェントが、バグ報告をコーディングエージェントに引き継ぐ
    • 小さなチーム 1つのエージェントが変更を書き、別のエージェントがレビューする
    • 部門 サポートエージェントが、返金の問い合わせを根拠とともに経理に回す
  3. 03

    今後の方向性

    チェーン

    エージェントが1つのプロセスとして連なります。1つが準備し、次が確認し、人が承認します。

    • 個人の創業者 ビルド、ストア掲載情報、スクリーンショット、申請までを、1回の承認で
    • 小さなチーム ブリーフ、クリエイティブのバリエーション、ブランド確認、公開
    • 部門 請求書を集めて照合し、承認用に準備する
  4. 04

    一部は現在利用可能

    自ら面倒を見るファミリー

    Dashboards は各エージェントの状態と支出を表示し、ツールは署名を確認したうえで自動的にアップデートされ、Observatory は変更内容を記録します。エージェント同士が互いを見守る仕組みは、今後の方向です。

    • 個人の創業者 どのエージェントがなぜ止まったかが、1つのウィンドウでわかる
    • 小さなチーム 請求が膨らむ前に、支出の上限でエージェントを止める
    • 部門 すべての変更を、担当したエージェントと承認した人までたどれる
  5. 05

    今後の方向性

    チーム

    人も同じループに加わります。それぞれがワークプレースと、自分の役割のエージェント、そしてできることの範囲を持ちます。

    • 個人の創業者 最初の採用者が受け継ぐのは、スクリプトの山ではなくエージェントです
    • 小さなチーム デザイナー、エンジニア、マーケターが1つのファミリーを共有する
    • 部門 測定したパイロットのあとで、役割ごとにワークプレースを展開する
  6. 06

    今後の方向性

    組織

    エージェントはすべてのワークプレースに行き渡ります。人は、エージェントの仕事を検証し、自分のエージェントも作る専門家として働き、そのエージェントがネットワークを通じて広がります。

    • 個人の創業者 定型業務を増やさずに、会社が成長する
    • 小さなチーム 1人が作った良いエージェントが、全員に届く
    • 部門 リーダーが見るのは、人がどれだけ忙しそうかではなく、プロセスがどう動いているかです

06 / 信頼

頼れるもの、
どの段階でも

セキュリティ

各エージェントが使えるのは、あなたが許可したツールとアカウントだけです。キーは保護されたローカルストレージに保管され、リリースは署名され、インストール前に検証されます。

データ

作業内容は、あなたのコンピュータとクラウドアカウントの中にとどまります。Fabric と Switchboard が送るのは匿名の利用回数だけで、オフにもできます。プライバシー

ロックインなし

GNU AGPL-3.0 のオープンソース、オープンなコントラクト、任意のコーディングエージェント、そしてあなた自身のモデルアカウントを使います。いつでもやめられ、すべてを手元に残せます。

信頼性

どのツールにも、公開されたテストコマンドとリリースノートがあり、まだ動かないことも率直に記しています。完了とは、証跡に照らして確認できたことです。

人

分析の対象は、エージェントと成果です。何が動き、いくらかかり、何が承認されたかを見ます。隠れた監視はなく、測定される内容は、その対象となる人に見えます。

おすすめのツール

始めた仕事を
最後までやり遂げるエージェント

ハーネスには、一つひとつの変更の中での規律も必要です。おすすめするのは task-pipelineは、次のファミリーに含まれる独立したオープンソースのスキルです：sshlg-skillsファミリーです。変更をゲート付きの段階に沿って進め、ブリーフと計画から、テスト、デプロイ、受け入れまでを扱い、各ゲートを通過するまで次へ進みません。Claude Code、Codex、そして Agent Skills を読むその他のエージェントで動作します。

npx sshlg-skills install

GitHub の task-pipeline · PassionCode.ai には含まれず、PassionCode.ai を必要ともしません

07 / 組織向け

同じ道筋を、
組織全体に

組織のAI導入は、上の道筋と同じ順序で進めます。まず測定するパイロット、次に役割ごとのワークプレース、そして従業員のマシン上のエージェントです。人は、仕事を検証し、自分のエージェントも作る専門家として関わります。PassionCode for Enterprise は、エージェントとプロセスの分析、コントロールとポリシー、従業員が自分の仕事を自動化するための支援、そしてお客様のクラウドか当社のクラウドかの選択を加えます。

組織向け →
  • ベースラインと比較して測定するパイロット1つのプロセスについて、時間とコストを測り、すべての操作を記録します
  • 役割ごとに展開するワークプレースエージェント、アカウント、そしてできることの範囲
  • エージェントとプロセスの分析何が動いたか、いくらかかったか、何が承認されたか
  • お客様のクラウドでも、弊社のクラウドでもそしてモデルは、お客様自身のプロバイダーアカウントで動かします

よくある質問

始める前に

PassionCode.ai は Claude Code や Codex の代わりになりますか？

いいえ。その上で動きます。作業はこれまでどおりコーディングエージェントが行い、PassionCode.ai はそのエージェントに、拠点、アカウント、状態管理、メモリ、証跡を与え、次のエージェントが同じファミリーに加われるようにします。

ここに書かれていることは約束ですか？

いいえ。このページの各段階には、「今日使えるもの」か「今後の方向」かを示しています。使えるものとして挙げたツールは今日ダウンロードできます。それ以外は開発中の方向で、この順で進めています。

PassionCode.ai は従業員を評価しますか？

いいえ。分析の対象はエージェントとプロセスの成果です。何が動いたか、いくらかかったか、何が承認されたかを見ます。人をひそかに監視することはなく、測定される内容は、その対象となる人に見える形になっています。
