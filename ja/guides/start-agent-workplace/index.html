20分でエージェントワークプレースを始める

自分のコンピューターにツールをセットアップするとき、各ステップで何が起きるかを説明します。1つのコマンドから、最初のエージェント、そして次のエージェントまで。

Sergey Sheleg（PassionCode.ai 共同創業者）

必要なもの

Node.js 18 以降が入ったコンピューターと、Claude Code または Codex が必要です。プロジェクトとそのエージェントのための拠点である Fabric は早期プレビュー版で、どのシステムでも Docker と Supabase CLI も必要です。すべてオープンソースで、個人利用は無料です。

コマンドを1つ実行する

macOS では、コマンド1つで、選んだツールを署名済みリリースからインストールし、その MCP サーバーをコーディングエージェントに接続し、スキルを追加します。Windows と Linux では、先にアプリをそれぞれのページからダウンロードしてから、同じコマンドでスキルと MCP サーバーを設定します。署名やチェックサムが合わないものは何もインストールしません。作業をコーディングエージェントに任せることもできます：コマンドとコーディングエージェント用のプロンプトは「はじめる」ページにあります。

コーディングエージェントを再起動して確認する

新しいツールを読み込むよう、Claude Code または Codex を再起動します。同じコマンドをもう一度実行するか、doctorを実行すると、何も変えずに点検できます：何が設定済みか、何が足りないか、サインインなどあなたにしかできない手順はどれかを教えてくれます。

最初のエージェントを作成する、または対応させる

必要なことをふだんの言葉でコーディングエージェントに頼むか、Fabric の作成（Create）と対応（Adapt）の操作から始めます。Fabric Agent Adapter スキルは、まず質問し、何かを変更する前に計画を示します。コントラクト、ダッシュボード、テストを備えたエージェントが得られます。

動いているところを見る

Fabric Dashboards は、ローカルのエージェントサービスをすべて1つのウィンドウに表示します：何をしているか、どれだけ使っているか。コーディングエージェントが代わりに起動、停止、表示することもできます。

次のエージェントを同じプロジェクトに追加する

次のエージェントも同じ方法で作り、Fabric の同じプロジェクトに割り当てます。Fabric につながったエージェントは、1つのプロジェクトのボード、メモリ、引き継ぎを共有するので、1つのエージェントが止めたところから別のエージェントが続けられます。

うまく動かないとき

コマンドをもう一度実行してください：すでにセットアップ済みのコンピューターでは、すべてを点検し、問題を修復し、何が変わったかを示します。各製品ページに、それぞれの要件と制限が記載されています。
