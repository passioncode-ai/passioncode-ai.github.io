課題

プロジェクトは
会話よりも長く続きます

エージェントがタスクを終えても、その理由がチームから失われることがあります。コンテキストはチャットに散らばり、決定は繰り返し説明する必要があり、誰かが作業をつなぎ直さなければなりません。

Fabricは、プロジェクトを軸に作っています。目的、チーム、決定、履歴を、次のセッションの後にも残すためです。

運用ループ · 方向性

意図から
確認済みの結果まで

これは私たちが目指しているワークフローです。Fabricの方向性を示すもので、すべてのステップが今すぐ使えることをお約束するものではありません。

  1. 01

    プロジェクトを理解する

    目的、現在の状況、関連するコンテキストを同じ場所に集めます。

  2. 02

    作業を明確にする

    目標を、担当者、期待する成果、明確な境界を持つ作業に落とし込みます。

  3. 03

    実行を調整する

    プロジェクトのコンテキストを失わずに、人、エージェント、繰り返し可能なプロセスの間で作業を振り分けます。

  4. 04

    レビューして学び続ける

    結果をエビデンスと照らして確認します。決定と学びは次のサイクルのために残します。

FABRICの中身

前回の続きから
あなたの判断が必要なこと

実際のFabricのウィンドウを、合成したデモスペース（4つのプロジェクトと28日分の作業）で表示しています。

どのように作っているか

責任は人にあります

CEOは調整役を表します。プロジェクトの目的と、エージェントに許可することを決めるのはあなたです。

権限

許可は明示的です

目標、責任、制限はプロジェクトのものです。エージェントの確信は、実行の許可にはなりません。

選択

エージェントは入れ替え可能です

プロバイダーや作業するエージェントを変えても、プロジェクトは目的と履歴を保てるべきです。

エビデンス

結果にはレシートが必要です

完了したタスクには、エージェントが「終わった」と言うだけでなく、人が確認できるものが付いているべきです。

FABRICを入手

早期プレビュー版
Mac 向け

最新のプレビュー版：0.3.3。FabricはMac上でローカルデータベースとともに動作し、プロジェクトはこのマシンの中にとどまります。

⌘

macOS

Apple silicon（arm64）· macOS 13以降
DMG インストーラー · Developer ID で署名され、Apple の公証済み

macOS 版をダウンロード ↓

DMGを開き、FabricをApplicationsにドラッグします。このプレビュー版ではIntel Macはサポートされていません。

☰

開く前に

FabricはDocker内のSupabase CLIで、専用のローカルデータベースを起動します。

  • Docker DesktopまたはOrbStack（起動中）
  • Supabase CLI：brew install supabase/tap/supabase
  • Claude CodeまたはCodex CLI（サインイン済み。エージェントが作業を行うために必要）

DockerまたはCLIがない場合、Fabricは初回起動時にどちらが不足しているかを知らせます。詳しくはFabricが対応するコーディングエージェントと、それぞれでできることをご覧ください。

これは早期プレビュー版です。プロジェクト、判断のボード、タスク、目標、作業の動き、レシート付きのリリースを保管できます。Fabricとの会話ではメッセージが保存されますが、Fabricはまだ応答しません。新しいバージョンでも既存のデータベースは自動ではアップグレードされず、実行するコマンドが案内されます。このMacに登録されたエージェントは、ローカルのエージェントハブを通じて、Fabric Inboxなどの接続済みプロダクトへのアクセスをFabricに求めることができます。各リクエストを許可するか拒否するかはあなたが決め、設定でいつでも取り消せます。0.3.2以降、Fabricは匿名の利用回数を送信します。送るのは回数と種類だけで、名前、パス、内容は送りません。設定の「Share usage counts」でオフにでき、この設定はMac上のすべてのPassionCode.aiアプリに適用されます。
