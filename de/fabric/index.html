DAS PROBLEM

Ein Projekt dauert länger
als ein Gespräch

Ein Agent kann eine Aufgabe abschließen, während das Team den Grund dahinter verliert. Kontext verteilt sich auf Chats, Entscheidungen müssen wiederholt werden, und jemand muss die Arbeit wieder zusammensetzen.

Wir bauen Fabric rund um das Projekt: den Zweck, das Team, die Entscheidungen und den Verlauf, die die nächste Sitzung überdauern sollen.

DER ARBEITSZYKLUS · RICHTUNG

Von der Absicht
zum geprüften Ergebnis

Das ist der Workflow, auf den wir hinarbeiten. Er beschreibt die Richtung von Fabric, nicht das Versprechen, dass jeder Schritt heute verfügbar ist.

  1. 01

    Das Projekt verstehen

    Zweck, aktuellen Stand und relevanten Kontext an einem Ort zusammenbringen.

  2. 02

    Die Arbeit konkret machen

    Aus dem Ziel Arbeit machen – mit Verantwortlichem, erwartetem Ergebnis und klaren Grenzen.

  3. 03

    Die Ausführung koordinieren

    Arbeit zwischen Menschen, Agenten und wiederholbaren Abläufen verteilen, ohne den Kontext des Projekts zu verlieren.

  4. 04

    Prüfen und weiterlernen

    Das Ergebnis anhand von Belegen prüfen. Entscheidungen und Erkenntnisse für den nächsten Zyklus festhalten.

BEFUGNISSE

FABRIC HOLEN

Eine frühe Vorschau
für deinen Mac

Neueste Vorschau: 0.3.2. Fabric läuft auf deinem Mac mit einer lokalen Datenbank; deine Projekte bleiben auf diesem Rechner.

⌘

macOS

Apple silicon (arm64) · macOS 13 oder neuer
DMG-Installer · mit Developer ID signiert und von Apple notarisiert

Für macOS herunterladen ↓

Öffne das DMG und ziehe Fabric in den Ordner „Programme“. Intel-Macs werden in dieser Vorschau nicht unterstützt.

☰

Bevor du es öffnest

Fabric startet seine eigene lokale Datenbank mit der Supabase CLI in Docker.

  • Docker Desktop oder OrbStack, laufend
  • Supabase CLI: brew install supabase/tap/supabase
  • Claude Code oder Codex CLI, angemeldet, damit Agenten arbeiten können

Fehlt Docker oder die CLI, sagt Fabric beim ersten Start, welches von beiden. Siehe mit welchen Coding-Agenten Fabric arbeitet und was jeder dort kann.

Release-Notes und Prüfsumme ↗Quellcode ansehen ↗

Das ist eine frühe Vorschau. Du kannst Projekte, ein Board mit Entscheidungen, Aufgaben, Ziele, einen Puls der Arbeit und Releases mit ihren Belegen führen. Das Gespräch mit Fabric speichert deine Nachrichten, aber Fabric antwortet noch nicht. Eine neuere Version aktualisiert eine bestehende Datenbank nicht von selbst; sie nennt dir den Befehl, den du ausführen musst. Auf diesem Mac registrierte Agenten können Fabric über seinen lokalen Agent-Hub um Zugriff auf ein verbundenes Produkt wie Fabric Inbox bitten; du erlaubst oder verweigerst jede Anfrage und kannst sie in den Einstellungen widerrufen. Seit 0.3.2 sendet Fabric anonyme Nutzungszahlen – nur Zahlen und Arten, niemals Namen, Pfade oder Inhalte; schalte sie unter Einstellungen → Nutzungszahlen teilen aus, was für jede PassionCode.ai-App auf deinem Mac gilt.

Fabric ist Open Source unter der GNU AGPL-3.0, und eine kommerzielle Lizenz ist erhältlich über passioncode.ai/business für eine Nutzung, die die AGPL nicht abdeckt. Die 0.3.2 Vorschau wird in der CI aus diesem öffentlichen Quellcode gebaut, signiert und notarisiert.
