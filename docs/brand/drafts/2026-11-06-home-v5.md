## 01 / THE PROBLEM

**H2:** Your processes were built for people. / More AI assistants do not change that.

Lead: Every company now gives its people AI assistants. The work still moves at the speed of the people in between.

Cards:

1. **The person is still the bottleneck.** An assistant drafts and analyzes, then hands the result back to a person. Ten assistants hand back ten results. The work waits until that person has time.
2. **Meetings reconcile what the assistants made.** Two people with their own assistants produce more than either can
   read. They meet to agree on it, and the process stays exactly as it was.
3. **Everyone builds their own agents.** No shared rules, no shared memory, keys pasted wherever they work, and no
   record of what an agent did or what it cost. It adds work instead of removing it.

Evidence line: Most companies now experiment with agents; few run them across a whole function (McKinsey, State of AI,
2025). Gartner expects over 40% of agentic AI projects to be canceled by the end of 2027.

## 02 / THE SHIFT

**H2:** Agents run the process. / People steer it.

| Today | AI-native |
| --- | --- |
| A person takes a task, holds it, hands it on | An agent takes the task and hands it to the next agent |
| Meetings reconcile the output | Agents settle it on the board, with the record |
| Each person's assistants, each person's rules | One system: the same rules, keys and record for every agent |
| More work means more people | More work means more agents |

People keep three jobs: **direction** (what to build and why, with taste), **control** (approving what needs a
person) and **expertise** (knowing the market and the craft, and teaching the agents). Running the system takes from
none to a few people.

## 04 / ONE SYSTEM

**H2:** Every agent built one way. / Every result on the record.

1. **Agents from templates.** Each agent starts from a template and one open contract, so an employee's agent works
   like every other and its mistakes are found the same way.
2. **Keys in one vault.** Agents use keys by name and never see them; each organization and each person is isolated
   from the others.
3. **Everything on the record.** Every task, run, cost and result is logged, so you can see what an agent did and
   what it cost.
4. **A dashboard for every role.** Each agent ships its own page and joins one view of what runs, what it costs and
   what it connects to. AVAILABLE NOW for each agent; dashboards per role are DIRECTION.

## 05 / AGENTS AT WORK

**H2:** What an agentic company looks like

Diagram (text alternative): People (owners, administrators, industry experts) give goals and approvals to Fabric's
board. The board assigns work to market research, analytics and signals, support, product and release, marketing and
content agents. They all read and write the data room: facts, metrics, releases, known issues. Assessment and
optimizer agents read the whole record; a security agent watches keys, access and new agents.

Three loops:

- **A user's question becomes a release.** Support answers from what the company knows; a new complaint becomes a
  signal; analytics confirms it; Fabric hands the fix to the product's agent and puts it in the release queue.
- **The market becomes a hypothesis.** Research keeps the data current; an expert reads it and writes a hypothesis;
  agents build the change and the experiment; the result decides.
- **One message, every language.** Marketing plans, the copy agent writes in the brand's voice and adapts every
  language, the media agent makes the visuals, and the posting agent sends it out.

Note: The roles exist today as separate agents; connecting all of them through one board is what Fabric is built for.

## Questions (two new)

- **Does this replace my team?** It changes what your people do. Agents take the work that moves between people;
  people set the direction, approve what needs a person and bring the expertise. What we measure is the work agents
  deliver, never people.
- **Where do my company's agents and data live?** On your own machines or in your own cloud, under your accounts.
  PassionCode administers them only if you ask, and sees configuration and spend, not your content, unless you agree.
