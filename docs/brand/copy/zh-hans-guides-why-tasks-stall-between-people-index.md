# 任务为什么卡在人与人之间，引入智能体后有什么变化

一项任务看上去在进行，其实可能在等下一个人看到它、接手它，或把它退回给计划员。智能体让这些检查和升级自动完成，改变了每天的工作节奏；任务归谁、怎么决定，仍由人负责。

Sergey Sheleg，PassionCode.ai 联合创始人

## 任务到底卡在哪里

先看交接环节：下一个人是否已经看到任务、接手了任务，还是认定它不归自己。这三件事一件都没发生时，任务可以一直开着，却没有人在做。

所以看板再忙，也可能藏着在等待的工作。实际要问的不只是谁最后动过这项任务，还有谁明确接下了下一步，以及没人接手时谁会收到通知。

## 交接停滞的迹象

留意三类信号：任务反复被退回，工作被挪到每周计划之外，周期以日历天数而不是工时计算。这些信号合在一起，能指出该检查哪段人与人之间的流程。

乒乓任务是指14天内又回到原来经手人的任务，评估会按流程统计这类退回次数。

在一家试点公司里，撰写产品文案的20项任务，周期中位数为9.8个日历天，按从开始到完成的天数计算，不是工时。

在同一家试点公司，计划员每周调整的任务中，有60%到85%不在当周任何计划里，统计区间为2026年5月25日至11月2日。

如果你对这些情形并不陌生，同样的交接视图也有助于说明为什么你的发布又延期了。

## 为什么手工催办无法扩展

手工催办让计划员变成了提醒系统：要发现沉默、再次询问、找到负责人、升级例外，同时还得保证计划前后一致。

任务经手的人越多，这套做法就越不均衡：有些没人回应的任务因为有人记得而得到关注，其他的继续等着。催得再用力，也补不上缺失的闭环。

更好的做法是把请求、回应和升级明确下来。这样计划员可以把时间用在厘清归属和解决阻塞上，不必再从聊天记录里还原当前状态。

## 智能体如何改变每天的工作节奏

智能体用固定的节奏取代临时催办：汇总当天的工作，明确归属，找出停滞的任务，升级无人回应的情况，并把仍在等待的决定交给创始人。

工作日 07:00，PM 智能体会问每个人今天在做什么，没有回复就稍后再提醒。

PM 智能体提出的每项任务都有三种回答：已看到、我来接、不归我；回答“不归我”的任务会立即转给计划员。

没人接手的任务，每 30 个工作分钟提醒一次；满 2 个工作小时后通知计划员，然后是副手，再然后是管理员。

10:00，PM 智能体列出几天没有进展的任务和每个人的阻塞项，计划员早上就能看到。

每天 21:00（包括周末），创始人会收到一份简短摘要：团队完成和推进了什么，有哪些决定在等人处理，什么最紧急。

## 智能体跟进工作，人来做决定

智能体跟进工作；这意味着什么、下一步怎么做，由人来决定。它让请求、回应和升级始终可见，但不接管优先级的决定权。

被退回“不归我”的任务，仍由计划员处理；等待人来决定的事项，仍由创始人处理。智能体的任务，是让这些例外送到人面前，而不是悄无声息地搁着。

## 如何从免费评估开始

先用一周只读观察，看清你自己的流程卡在哪里，而不是再增加一套手工汇报。

免费评估只给一个 agent 一周的只读权限，用来读取过去 90 天的任务跟踪、代码仓库、文档、团队聊天、邮件和客服记录；第七天，创始人会拿到一份流程地图、计划与实际的对照、各处的等待，以及建议先交给 agent 的工作，报告只给出群组和流程的汇总，不给任何个人打分。
