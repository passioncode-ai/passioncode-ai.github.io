### サイドパネルのエージェント

Claude CodeまたはCodexがメールウィンドウ右側のパネルで動き、このInboxにすでに接続されていて、アプリでできることは何でもできます。開くには、ツールバーのボタン、View → Agent Console、または⌃⌘T（WindowsとLinuxではCtrl+Shift+T）を使います。セッションごとに、選んだレベルの専用キーが発行され、セッションが終わるとそのキーは失効します。Mac App Store版にはコンソールがありません。

エージェントがセットアップ

### コピーするアドレスもシークレットもなし

コーディングエージェントがお客様のCloudflareアカウントにサーバーを作成し、アプリで許可すると自分で接続します。お客様はトークンを貼り付け、サインインし、Allowを選ぶだけです。ウェルカム画面には次の項目があります：Use the server your agent set up。

### サーバーが受け取れなかったメール

受け付けることも拒否することもできなかったメッセージは、ドメインの設定に宛先、日時、理由とともに表示されます。送信者にはバウンス通知が届いている可能性があるので、誰に確認すればよいかがわかります。

## 返信するものを減らす

Inboxはすべてのアカウントを同じ方法で仕分けし、お持ちのドメインのアドレスには対応する担当を用意します。

重要なものを先頭に

### あなたの対応が必要なものを上に

人からの未読メール、セキュリティやサインインのメール、監視アラート、アプリ審査のリジェクト、決済の失敗、ビルドの失敗が先頭に並びます。ニュースレター、通知、請求などその他は、件数付きの折りたたみグループにまとまります。各行には、そこにある理由が表示されます。

お持ちのドメイン

### すべてのアドレスを1か所に

Cloudflareアカウントのドメインでメールを有効にし、すでにあるアドレスを取り込み、新しいアドレスを追加します。既存の各アドレスは、これまでの転送先へコピーを転送し続けます。メールボックスのないアドレス宛てのメールは一覧に表示され、破棄されることはありません。

ルールの範囲内でエージェントが対応

### 許可されたものだけを送信

エージェントは、それぞれ独自の指示、知識、ツールを持ち、複数のアドレスを担当できます。返信を送るのは、その内容が自身の知識に基づき、あなたが許可したトピックに収まり、1日の上限内である場合だけです。それ以外は、理由を添えた下書きとして待機します。

## エージェントにもできます

お使いのサーバーは、次の場所でModel Context Protocolに応答します：/mcp。アプリの各機能はMCPツールでもあるため、Claude Codeなどの別のMCPクライアントが、キーの権限レベルの範囲でメールの読み取り、仕分け、送信、アドレスの管理を行えます。

01

### エージェントに一文を渡す

アプリで 設定 → Agent accessを開きます。まず、コーディングエージェントに渡す一文が表示されます。エージェントがお客様のCloudflareアカウントにサーバーを作成し、Allowを選ぶと自分で接続します。アドレスもシークレットもコピーしません。エージェントの手順は次のガイドにあります：エージェント向けセットアップガイド。

02

### または自分でキーを作成する

同じ画面で、名前、レベル（read、mail、admin）、送信を許可するかどうかを選びます。シークレットは1回だけ表示されます。

03

### エージェントを接続する

自分で作成したキーなら、アプリがコマンド全体を表示します：claude mcp add --transport http fabric-inbox https://<your-server>/mcpキーの2つのヘッダーが含まれます。その後、次のように依頼します：list_accounts。

## Inboxの現状

メールはどこに届きますか？

アプリがお客様自身のCloudflareアカウントに作成するサーバーに届きます。Gmailアカウントは、ご自身のGoogle Cloudプロジェクトで作成したOAuthクライアント経由で接続します。

メールに自動で返信しますか？

エージェントを割り当てたアドレスに限り、そのルールが許す返信だけを行います。自動送信メール、一括メール、送信専用メールには返信せず、実行のたびに何を送ったかを正確に記録します。

どんなメールアカウントでも使えますか？

まだです。プレビュー版ではCloudflareのメールボックスとGmailが使えます。汎用のIMAPとOutlookへの対応は計画中です。

ソースは公開されていますか？

はい。Fabric InboxはGNU AGPL-3.0のオープンソースです。AGPLの対象外となる用途向けの商用ライセンスは、passioncode.ai/businessから入手できます。もとはCloudflareのAgentic Inboxテンプレートで、そのApache-2.0の表示はそのまま残しています。リポジトリにソース、テスト、リリースノートが含まれます。

InboxはFabricのエージェントですか？

いいえ。Inboxはメールクライアントで、そのエージェントはあなたが決めたルールの範囲でアドレスに対応します。Fabricは早期プレビュー版で、プロジェクトとそのエージェントのための拠点です。同じツールキットに属し、役割が異なります。
