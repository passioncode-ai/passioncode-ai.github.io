エージェントは始めるのは簡単でも、続けるのは難しいものです。私たちは、エージェントをつなぎとめる仕組みを作っています。新しいエージェントが加わるたびに、ほかのエージェントも強くなるように

01 / エージェントを支えるもの

## 問題はモデルではありません。

## それを支えるものです

多くの組織がすでにエージェントを試していますが、どの業務領域でも、規模を広げられているのは10%以下です。単独で作られたエージェントは、セッションが変わると忘れ、自分のアカウントも見失います。何をしたかの記録を残さず、次のエージェントはそのことを何も知りません。エージェントをつなぎとめるものを、私たちはこう呼んでいます。ハーネス（harness）：モデルを取り巻き、エージェントが長く働き続けられるようにするものすべてです。主要なAIラボもこの言葉を使っています：Anthropic, OpenAI。

01

### 拠点

各プロジェクトには、目的、ボード、意思決定、リリースを置く場所が1つあり、そのプロジェクトで働くすべてのエージェントが共有します。それが Fabric です。

02

### アカウント

各エージェントは、使うべきアカウントで、上限を確認しながら動きます。それが Fabric Switchboard です。

03

### 状態とコントロール

すべてのエージェントサービスについて、何をしているか、どれだけ使っているかを、人もエージェントも操作できる1つのウィンドウで確認できます。それが Fabric Dashboards です。

04

### メモリと証跡

何が変わったか、何が決まったか、何に注意が必要かを、根拠とともに残します。それが Project Observatory です。

02 / 私たちの考え

## 4つの原則に

## 沿って作っています

プロジェクトが軸どのエージェントもプロジェクトのために働き、プロジェクトが目的、決定事項、リリースを保持します。だから、仕事はそれを行ったセッションより長く残ります。

仕事が自ら良くなる実行は開いて確かめられる証跡を残し、今日は Observatory がそれを保管しています。それを次のエージェントが学べる教訓に変える振り返りは、これから目指す方向です。

どのエージェントでも、お使いのマシンでベンダー中立でローカルファースト、GNU AGPL-3.0 のオープンソースで、Claude Code や Codex、そしてその先のツールの上で動きます。

分析であって、監視ではない分析の対象は、エージェントとプロセスの成果です。人をひそかに監視することはありません。

### チェーン

エージェントが1つのプロセスとして連なります。1つが準備し、次が確認し、人が承認します。

04

一部は現在利用可能

### 整った状態に保たれるエージェント

Dashboards が各エージェントの状態と支出を示し、ツールは自動で更新され、Observatory が変更を記録します。エージェント同士が見守り合うことは、これから目指す方向です。

今後の方向性

### チーム

人も同じループに加わります。それぞれがワークプレースと、自分の役割のエージェント、そしてできることの範囲を持ちます。
