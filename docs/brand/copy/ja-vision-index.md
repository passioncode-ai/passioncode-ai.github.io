02 / 欠けているハーネス

## 問題はモデルではありません。

## それを支えるものです

ハーネス（harness）とは、 モデルの周りにあって、エージェントを長く安定して動かすためのすべてを指します。作業する場所、使えるツールとアカウント、セッションをまたいで覚えておくこと、作業が通るべきチェック、そして行ったことの記録です。モデルを開発している研究機関も同じ言葉を使っており、Anthropic は長時間動くエージェントのための効果的なハーネス（2025年11月）について、OpenAI はハーネスエンジニアリング（2026年2月）について書いています。

01

### 拠点

各プロジェクトには、目的、ボード、意思決定、リリースを置く場所が1つあり、そのプロジェクトで働くすべてのエージェントが共有します。それが Fabric です。

02

### アカウント

各エージェントは、使うべきアカウントで、上限を確認しながら動きます。それが Fabric Switchboard です。

03

### 状態管理とコントロール

すべてのエージェントサービスについて、状態、支出、アップデートを、人もエージェントも操作できる1つのウィンドウで確認できます。それが Fabric Dashboards です。

04

### メモリと証跡

何が変わったか、何が決まったか、何に注意が必要かを、根拠とともに残します。それが Project Observatory です。

これらをつなぐのは1つのコントラクトです。オープンなFabric Agent Contractです。Fabric Agent Adapter スキルは、どのコーディングエージェントにもこれに合わせた作り方を教えるので、今日作ったエージェントは、書き直さずにファミリーへ加われます。

03 / 私たちの考え

## 6つの原則に

## 沿って作っています

自分のものとして持てるエージェントあなたのマシンとあなたのアカウントで動き、コードは GNU AGPL-3.0 のもとで誰でも読めます。

あらゆるエージェントベンダー中立。Claude Code や Codex、そしてその先のツールの上に載るハーネスであり、それらの代わりにはなりません。

必要に応じて育てる1つの仕事に1つのエージェントから始めます。次のエージェントは、計画に書いてあるからではなく、仕事が求めたときに加えます。

信頼ではなく証跡すべての操作が、読める記録として残ります。完了とは、報告されたことではなく、確認されたことです。

決めるのは人エージェントは仕事を準備し、確認し、進めます。何をしてよいかを決め、重要なことを承認するのは人です。

常に可視化し、隠れて動かさない分析の対象は、エージェントとプロセスの成果です。人をひそかに監視することはありません。

### セキュリティ

各エージェントが使えるのは、あなたが許可したツールとアカウントだけです。キーは保護されたローカルストレージに保管され、リリースは署名され、インストール前に検証されます。

### ロックインなし

GNU AGPL-3.0 のオープンソース、オープンなコントラクト、任意のコーディングエージェント、そしてあなた自身のモデルアカウントを使います。いつでもやめられ、すべてを手元に残せます。

### 信頼性

どのツールにも、公開されたテストコマンドとリリースノートがあり、まだ動かないことも率直に記しています。完了とは、証跡に照らして確認できたことです。

分析の対象は、エージェントと成果です。何が動き、いくらかかり、何が承認されたかを見ます。隠れた監視はなく、測定される内容は、その対象となる人に見えます。
