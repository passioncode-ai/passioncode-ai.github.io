# Warum dein Release immer wieder rutscht: was ein Team-Assessment zeigt

Ein Release geht erst raus, wenn auch alles rund um den Code bereit ist. Ein Team-Assessment liest, wie die Arbeit in den letzten 90 Tagen tatsächlich lief, und zeigt, wo sie wartete. So beseitigst du das Warten, statt das Team anzutreiben.

Sergey Sheleg, Mitgründer von PassionCode.ai

## Wo ein Release wirklich wartet

Wenn ein Termin rutscht, geht die erste Frage meist an die Entwicklung. Das Assessment schaut zuerst an den Code vorbei. Ein Release wartet auch auf eine Entscheidung, die noch niemand getroffen hat, auf die Texte für einen Screen oder eine Store-Seite, auf ein Review oder auf eine Aufgabe, die so lange zwischen Personen hin und her ging, bis sie keinen Besitzer mehr hatte. Nichts davon taucht als Code auf. Ein Plan, der um den Code herum gebaut ist, sieht es deshalb nicht.

## Was das Assessment liest

Ein Agent verbindet sich mit den Systemen, die dein Team schon nutzt, und bekommt nur Lesezugriff: Tracker, Repositories, Dokumente, Team-Chats, Mail und Support. Er liest die letzten 90 Tage und begleitet die Arbeit danach eine Woche live. Er erstellt eine Karte der Aufgabenarten, zeigt, wie lange jede Art vom Start bis zum Abschluss dauert, und wie die Arbeit zwischen Personen und Systemen wandert. Er berichtet Summen für Gruppen und Prozesse, nie eine Bewertung einzelner Personen.

## Drei Dinge, die es meistens findet

Wartezeiten, die nicht Code sind. Das Assessment misst die Durchlaufzeit pro Aufgabenart: die Tage vom Start einer Aufgabe bis zu ihrem Abschluss. In einem Pilotunternehmen hatten die 20 Aufgaben zum Schreiben von Produkttexten im Median eine Durchlaufzeit von 9,8 Tagen. Das sind Kalendertage, keine Arbeitsstunden: Die Differenz ist Zeit, in der die Aufgabe wartete.

Arbeit außerhalb des Plans. Das Assessment vergleicht, was für eine Woche geplant war, mit dem, was sich bewegte. Im selben Pilotunternehmen standen 60 bis 85 % der Aufgaben, die die Planer in einer Woche bewegten, in keinem Plan dieser Woche. Gemessen wurde über die Wochen vom 25. Mai bis 2. November 2026. Ein Teil davon war Nacharbeit aus früheren Wochen, Reviews und Bugs. Der Rest war Arbeit, die der Plan nie enthielt.

Ping-Pong-Aufgaben. Eine Aufgabe kehrt innerhalb von 14 Tagen zu der Person zurück, die sie schon hatte. Jede Rückkehr heißt: Der nächste Schritt war unklar, oder niemand besaß die Entscheidung. Das Assessment zählt diese Rückläufer pro Prozess, damit du siehst, welche Übergaben immer wieder scheitern.

## Warum ein besserer Plan allein nicht reicht

Ein Plan listet die Arbeit auf, die jemand erwartet hat. Ein Release rutscht aber wegen der Arbeit, die niemand aufgelistet hat: die Entscheidung, die auf ein Meeting wartet, der Text, der auf seine Autorin oder seinen Autor wartet, die Aufgabe ohne Besitzer. Ein engerer Plan trifft eine Woche später auf dieselben Wartezeiten. Was hilft, ist ein Tagesrhythmus, der eine festhängende Aufgabe noch am selben Tag findet und die richtige Person fragt, bevor es eine Woche kostet.

## Was sich ändert, wenn ein Agent den Rhythmus führt

Der PM-Agent übernimmt die Routine, der Arbeit zu folgen, und jede Stunde seines Tages bleibt eine Einstellung, die du ändern kannst:

07:00, der Check-in. An Arbeitstagen fragt er jede Person, woran sie heute arbeitet, und erinnert später, wenn keine Antwort kommt.

Drei Buttons. Jede Aufgabe, die er aufbringt, hat drei Antworten: gesehen, übernehme ich, nicht meine. „Nicht meine“ geht sofort an den Planer, damit eine Aufgabe ohne Besitzer noch am selben Morgen einen bekommt.

Die Eskalationsleiter. Eine Aufgabe, die niemand übernimmt, löst alle 30 Arbeitsminuten eine Erinnerung aus. Nach 2 Arbeitsstunden erfährt es der Planer, dann die Vertretung, dann der Administrator.

10:00, liegengebliebene Aufgaben. Er listet die Aufgaben auf, die seit Tagen nicht vorangekommen sind, und die Blocker pro Person, damit der Planer sie morgens sieht.

21:00, der Bericht für die Gründer. Jeden Tag, auch am Wochenende, bekommen die Gründer eine kurze Zusammenfassung: was das Team abgeschlossen und bewegt hat, welche Entscheidungen auf Personen warten und was kritisch ist.

## Wer entscheidet

Agenten erledigen die Arbeit, Menschen entscheiden. Ein Agent schreibt den Entwurf, die Erinnerung oder den Bericht. Ein Mensch gibt frei, was das Unternehmen verlässt oder Geld berührt, setzt die Ziele und korrigiert den Agenten, wenn er falschliegt. Das Assessment zeigt, welche Arten von Arbeit ein Agent von Anfang bis Ende übernehmen kann und wo ein Mensch bleibt.

## So startest du

Starte mit dem kostenlosen einwöchigen Assessment. Du beantwortest vier Fragen und gibst Lesezugriff, ein Link pro System. Am siebten Tag bekommst du die Karte deiner Prozesse, Plan gegen Fakt, die Wartezeiten und ein Angebot: welche Arbeit Agenten zuerst übernehmen. Schreib dazu Morpheus, unserem PM-Agenten, auf Telegram, oder lies, wie das kostenlose einwöchige Assessment funktioniert.

## Quellen und Methode

Die Zahlen zu Durchlaufzeit und Plan stammen aus einem Pilotunternehmen, gelesen von unserem Assessment-Agenten; das Unternehmen wird nicht genannt. Die Durchlaufzeit wird in Kalendertagen pro Aufgabe gemessen, nicht in Arbeitsstunden. Die Messung nach der Umstellung beginnt am 7. Dezember 2026. Die Zeiten, Buttons und die Eskalationsleiter des PM-Agenten sind seine Standardeinstellungen.
