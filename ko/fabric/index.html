Fabric은 각 프로젝트의 목적, 보드, 결정, 릴리스를 내 컴퓨터에 보관하고, 그 프로젝트에서 일하는 모든 에이전트가 함께 씁니다. 우리는 Fabric이 내 에이전트들의 CEO 역할을 하도록 만들고 있습니다

문제

프로젝트는
대화보다 오래갑니다

에이전트가 작업을 끝내도 팀은 그 이유를 잃을 수 있습니다. 맥락은 여러 채팅에 흩어지고, 결정은 되풀이해야 하며, 누군가는 작업을 다시 이어 붙여야 합니다.

Fabric은 프로젝트를 중심으로 만들고 있습니다. 목적, 팀, 결정, 이력은 다음 세션 이후에도 남아야 하기 때문입니다.

운영 루프 · 방향

의도에서
확인된 결과까지

우리가 지향하며 설계하고 있는 워크플로입니다. Fabric이 나아갈 방향을 설명할 뿐, 모든 단계를 지금 사용할 수 있다는 약속은 아닙니다.

  1. 01

    프로젝트 파악

    목적, 현재 상태, 관련 맥락을 한곳에 모읍니다.

  2. 02

    작업을 명확하게

    목표를 담당자, 기대 결과, 분명한 경계가 있는 작업으로 바꿉니다.

  3. 03

    실행 조율

    프로젝트의 맥락을 잃지 않고 사람, 에이전트, 반복 가능한 프로세스 사이에서 작업을 배분합니다.

  4. 04

    검토하고 계속 배우기

    결과를 증거와 대조해 확인합니다. 결정과 배운 점은 다음 주기를 위해 남겨 둡니다.

FABRIC 내부

중단한 지점
내 결정이 필요한 일

실제 Fabric 창이며, 가상의 데모 공간(프로젝트 4개, 28일 분량의 작업)으로 보여 드립니다.

만들기와 맞추기 화면은 Fabric 자체 인터페이스를 소스 코드에서 샘플 데이터로 렌더링한 것입니다. 콘솔 텍스트는 코딩 에이전트가 하는 일을 직접 쓴 예시이며 녹화가 아닙니다.

만드는 방식

책임은 사람에게 있습니다

조율은 Fabric이 나아가는 방향이며, 사용자를 대신하지 않습니다. 프로젝트의 목적과 각 에이전트에게 허용할 일은 사용자가 정합니다.

권한

허용은 명시적으로

목표, 책임, 한계는 프로젝트에 속합니다. 에이전트가 확신한다고 해서 실행해도 된다는 뜻은 아닙니다.

선택

에이전트는 교체할 수 있습니다

제공업체나 작업하는 에이전트를 바꿔도 프로젝트는 목적과 이력을 그대로 유지해야 합니다.

증거

결과에는 영수증이 필요합니다

완료된 작업에는 에이전트의 완료 보고만이 아니라 사람이 직접 확인할 수 있는 무언가가 함께 있어야 합니다.

☰

열기 전에

Fabric은 Docker 안에서 Supabase CLI로 자체 로컬 데이터베이스를 시작합니다.

  • macOS: 실행 중인 Docker Desktop 또는 OrbStack, 그리고 Supabase CLI: brew install supabase/tap/supabase
  • Windows: 실행 중인 Docker Desktop(WSL2), 그리고 Supabase CLI: scoop install supabase
  • Linux: 실행 중인 Docker Engine, 그리고 Supabase CLI
  • 에이전트가 작업하려면 로그인된 Claude Code 또는 Codex CLI

Docker나 CLI가 없으면 Fabric이 처음 시작할 때 어느 쪽인지 알려 줍니다. Fabric과 함께 쓸 수 있는 코딩 에이전트와 각 에이전트가 Fabric에서 할 수 있는 일을 확인하세요.

Windows와 Linux에서는 아직: 코딩 에이전트에 로그인되어 있는지 Fabric이 읽지 않으며, 그렇다고 알려 줍니다. Windows에서는 아직: Project Observatory를 통한 클라우드 제품 시크릿 연결.

릴리스 노트 및 체크섬 ↗소스 보기 ↗

이 버전은 초기 프리뷰입니다. 프로젝트, 결정 보드, 작업, 목표, 작업 흐름 요약, 영수증이 붙은 릴리스를 보관할 수 있습니다. Fabric과의 대화는 메시지를 저장하지만 Fabric은 아직 답하지 않습니다. 새 버전이 기존 데이터베이스를 자동으로 업그레이드하지는 않으며, 실행할 명령을 알려 줍니다. 이 Mac에 등록된 에이전트는 로컬 에이전트 허브를 통해 Fabric Inbox 같은 연결된 제품에 대한 접근을 Fabric에 요청할 수 있습니다. 각 요청은 사용자가 허용하거나 거절하며, 설정에서 언제든 접근을 철회할 수 있습니다. 0.3.2부터 Fabric은 익명 사용 횟수를 전송합니다. 횟수와 종류만 보내며 이름, 경로, 내용은 보내지 않습니다. 설정 → 사용 횟수 공유에서 끌 수 있으며, 이 설정은 Mac의 모든 PassionCode.ai 앱에 적용됩니다.

Fabric은 GNU AGPL-3.0 오픈 소스이며, AGPL이 다루지 않는 용도를 위한 상용 라이선스는 passioncode.ai/business에서 받을 수 있습니다. 0.3.11 프리뷰는 공개된 해당 소스에서 CI로 빌드, 서명, 공증됩니다.

FABRIC과 함께

집을 둘러싼 네 가지 도구
각각 따로도 작동합니다

Fabric은 프로젝트를 지킵니다. 이 네 가지 도구는 Fabric과 함께, 또 각자 따로 작동하므로 어느 것부터 시작해도 됩니다.

Fabric Switchboard각 에이전트가 실행될 계정을 고르고, 사용량 한도를 한눈에 확인합니다.↗ Fabric Dashboards모든 로컬 에이전트 서비스를 한 창에서, 직접 또는 에이전트로 제어합니다.↗ Project Observatory모든 프로젝트에서 무엇이 바뀌었고 무엇에 주의가 필요한지 증거와 함께 보여 줍니다.↗ Fabric InboxGmail과 Cloudflare 메일을 한 목록에 모아 중요한 것부터 보여 주고, 에이전트는 정책에 따라 답장합니다.↗
