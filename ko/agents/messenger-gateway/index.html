01 / 기능

기능

  • 계정은 한곳에메신저 계정과 봇은 하나의 서비스에 있으며, 다른 어떤 에이전트도 이를 보유하지 않습니다.
  • 에이전트별 권한각 에이전트는 필요한 권한만 받습니다: 읽기, 검색, 보내기 또는 그룹 관리.
  • 발송은 사람이 승인합니다소유자가 상시 규칙을 정하지 않았다면 메시지는 사람의 승인을 기다립니다.

02 / 대상

대상

에이전트가 Telegram에서 사람들과 대화하지만 각자 계정을 가져서는 안 되는 조직에 적합합니다.

얻는 것

  • 프로젝트마다 흩어진 봇 토큰 없음
  • 보낸 모든 메시지의 기록
  • 모든 발송을 멈추는 하나의 스위치

03 / 구성 방식

템플릿이
조직의 에이전트가 되기까지

템플릿에는 저희가 이런 종류의 에이전트를 운영하며 배운 것이 담겨 있습니다. 저희 엔지니어 에이전트가 조직에 맞춰 구성하며, 세부 내용은 요청 시 제공합니다.

  1. 01

    조직의 프로세스에서 시작합니다

    에이전트가 무엇을 해야 하는지 알려 주세요. 저희는 에이전트가 맡을 일, 필요한 시스템, 누가 무엇을 승인하는지 살펴봅니다.

  2. 02

    저희 엔지니어 에이전트가 구성합니다

    알맞은 템플릿을 골라, 허용하신 접근 권한으로 조직의 시스템을 연결하고, 조직의 규칙과 지출 한도를 설정합니다.

  3. 03

    원하는 곳에서 실행됩니다

    조직의 컴퓨터나 자체 클라우드에서, 조직의 키로 실행됩니다. 각 에이전트는 상태와 지출을 보여 주며, 사람이 필요한 일은 사람이 승인합니다.
