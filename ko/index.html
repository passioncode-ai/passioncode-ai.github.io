    지금 사용 가능

    에이전트 하나

    Claude Code, Codex 또는 다른 코딩 에이전트로 한 가지 일을 맡을 에이전트를 만듭니다. Fabric Agent Adapter 스킬이 계약, 대시보드, 테스트를 붙여 줍니다.

  2. 02

    지금 사용 가능

    서로 대화하는 에이전트 둘

    Fabric에 연결된 에이전트들은 한 프로젝트의 보드, 메모리, 인계를 함께 씁니다. 한 에이전트가 멈춘 지점에서 다음 에이전트가 이어받고, 모든 인계는 직접 읽어 볼 수 있습니다.

  3. 03

    방향

    에이전트 체인

    에이전트들이 하나의 프로세스로 이어집니다. 하나가 준비하면 다음이 검토하고, 사람이 승인합니다.

  4. 04

    일부 지금 사용 가능

    스스로 관리하는 패밀리

    Fabric Dashboards가 각 에이전트의 상태와 비용을 보여 주고, 도구는 스스로 업데이트되며, Project Observatory가 무엇이 바뀌었고 무엇이 결정되었는지 기록합니다. 에이전트가 서로를 지켜보는 것은 앞으로의 방향입니다.

  5. 05

    방향

    팀

    같은 루프에 사람들을 초대합니다. 각자 업무 공간과 자신의 역할에 맞는 에이전트, 그리고 허용된 권한을 받습니다.

  6. 06

    방향

    조직

    에이전트가 모든 업무 공간에 닿고, 사람은 검증하고 자신만의 에이전트를 만들며, 조직은 일이 어떻게 돌아가는지 한눈에 봅니다.

도구를 줄줄이 엮고, 각 부품이 어떻게 맞물리는지 익히고, 기계가 할 수 있는 일을 손으로 하는 데서 벗어나세요. 말로 시작하세요. 필요한 것을 만들어 달라고 하면 됩니다. 업무 공간은 함께 자랍니다. 에이전트가 반복 업무를 하나씩 덜어 주니, 주마다 정말 즐기는 일에 쓸 시간이 늘어납니다.

  • 시작은 간단하게파이프라인이 아니라 말로 합니다. 원하는 결과를 설명하면 에이전트가 단계를 만듭니다.
  • 로컬, 오픈 소스내 컴퓨터에서, 누구나 읽을 수 있는 코드로, GNU AGPL-3.0 아래 실행됩니다.
  • 설계부터 안전하게각 에이전트가 할 수 있는 일을 직접 정하고, 모든 동작은 증거로 남습니다.
  • 내 방식대로아무것도 없는 상태에서 무엇이든, 직접 또는 에이전트로 구성합니다.
  • 모든 에이전트Claude Code, Kilo Code, Hermes Agent는 지금 Fabric에 연결할 수 있고, Codex와 Cline은 Fabric 안에서 실행되며, 더 많은 에이전트를 계획하고 있습니다. 어떤 에이전트를 어느 수준으로

현재는 명령어 하나와 코딩 에이전트로 시작합니다. Fabric과의 대화로 시작하는 것이 Fabric이 향하는 방향입니다.

01 / 작동 방식

빈 Mac에서
에이전트가 일하는 곳까지

네 단계이며, 각 단계는 그 자체로 쓸모가 있습니다. 필요한 단계부터 시작하고 나머지는 일이 필요할 때 추가하세요.

  1. 01

    업무 공간 만들기

    명령어 하나로 에이전트 스킬을 설치한 다음 Fabric을 추가하세요. Fabric은 모든 프로젝트에 목적, 보드, 결정, 릴리스를 담는 공간을 만들어 주는 CEO AI 에이전트입니다.

    npx @passioncode-ai/passioncode@latest update

    Fabric 초기 프리뷰 0.3.2 Apple silicon용 macOS · 런처 0.1.31

    단계별 가이드 →
  2. 02

    에이전트 만들기

    릴리스 퍼블리셔, 지원 요청 분류, 주간 리포트처럼 필요한 에이전트를 Claude Code나 Codex에 요청하세요. Fabric Agent Adapter 스킬이 자체 계약, 대시보드, 테스트를 갖춘 서비스로 만들어 줍니다. 앞으로는 Fabric이 대화만으로 이 일을 해 줄 예정이며, 지금은 코딩 에이전트가 같은 스킬로 합니다.

    나 병합된 풀 리퀘스트로 릴리스 노트 초안을 작성하는 Fabric 에이전트를 만들어 줘

  3. 03

    이미 있는 것을 변환하기

    에이전트, MCP 서버, 명령줄 도구, 또는 프로젝트 전체를 다시 작성하지 않고 Fabric과 호환되는 서비스로 만들 수 있습니다. 부족한 부분은 적합성 프로브가 알려 줍니다.

    나 이 저장소를 Fabric에 맞게 변환해 줘

    Fabric Agent Adapter 0.8.1 · Fabric Agent Contract

  4. 04

    실행하고 모든 것을 확인하기

    Fabric Dashboards는 모든 서비스를 한 창에 보여 주고, 에이전트가 서비스를 시작하고 중지할 수 있게 합니다. Switchboard는 각 에이전트가 실행될 계정을 고릅니다. Project Observatory는 모든 프로젝트에서 무엇이 바뀌었는지 증거와 함께 보여 줍니다.

    도구 선택 ↓

처음부터 끝까지 내 것입니다. 모든 것이 내 컴퓨터와 내 계정에서 실행됩니다. 모든 코드는 GitHub에 GNU AGPL-3.0으로 공개되어 있습니다. 가입도, 비용도 없고, 특정 모델이나 업체에 묶이지 않습니다.

07 / 질문

가장 먼저 받는 질문

PassionCode.ai는 무료인가요?

네. 모든 도구는 GNU AGPL-3.0 오픈 소스이므로 무료로 다운로드하고 사용하고 살펴보고 수정할 수 있습니다. 폐쇄형 제품에 포함하거나 수정한 호스팅 서비스를 소스 공개 없이 운영해야 한다면 상용 라이선스를 이용할 수 있습니다.

어떤 에이전트와 함께 쓸 수 있나요?

특정 에이전트에 묶여 있지 않습니다. Claude Code, Kilo Code, Hermes Agent는 지금 Fabric에 연결할 수 있고, Codex와 Cline은 Fabric 안에서 실행되며, 더 많은 에이전트를 계획하고 있습니다: 수준별 전체 목록. 어떤 에이전트, MCP 서버, 명령줄 도구든 Fabric Agent Adapter로 Fabric과 호환되는 서비스로 만들 수 있습니다.

기존 프로젝트나 에이전트를 Fabric 에이전트로 바꾸려면 어떻게 하나요?

PassionCode.ai 런처(npx @passioncode-ai/passioncode@latest update)를 설치한 뒤 코딩 에이전트에게 프로젝트를 Fabric에 맞게 변환하라고 요청하세요. Fabric Agent Adapter 스킬이 계약, 대시보드, 적합성 검사를 갖춘 서비스로 감싸 줍니다. 가이드에서 단계를 확인할 수 있습니다.

Fabric이 에이전트를 스스로 만드나요?

아직은 아닙니다. Fabric은 초기 프리뷰이며, 각 프로젝트의 보드, 결정, 릴리스를 관리하지만 대화에는 아직 응답하지 않습니다. 대화로 에이전트를 만드는 것은 앞으로의 방향이며, 지금은 코딩 에이전트가 Fabric Agent Adapter 스킬로 합니다.

내 데이터는 어디로 가나요?

작업 내용은 내 컴퓨터와 내 클라우드 계정에 남습니다. Fabric Switchboard와, 버전 0.3.2부터는 Fabric이 익명 사용 횟수를 보냅니다. 횟수와 종류만 보내며 이름, 경로, 내용은 절대 보내지 않습니다. Switchboard의 정보 창이나 Fabric의 설정에서 끌 수 있습니다. 정확히 무엇이 전송되나요.
