02 / 재무와 엔지니어링을 위해

에이전트가 쓴 비용과
만들어 낸 결과를 한 화면에

재무와 엔지니어링(CFO, 그리고 CTO 또는 CIO)은 에이전트를 서로 다른 쪽에서 봅니다. 엔지니어링은 에이전트를 더 원하고, 재무는 에이전트에 쓴 1달러까지 설명되기를 원합니다. 두 쪽 모두 같은 질문을 합니다. 각 에이전트에 얼마가 들었고, 무엇을 해냈는가? 이것이 각 에이전트의 ROI입니다. 그 답이 양쪽이 함께 여는 하나의 기록이 되면, 에이전트를 늘리는 일은 숫자가 뒷받침하는 결정이 됩니다.

  1. 01

    지금 사용 가능

    업무가 에이전트를 거쳐 진행되나요, 아니면 옆에서만 쓰이나요?

    추정치는 각 프로세스가 지금 어떻게 진행되는지에서 시작합니다. 수작업인지, 스크립트인지, 가끔 쓰는 채팅 어시스턴트인지, 이미 에이전트가 일부를 맡고 있는지입니다. 그다음 파일럿에서 한 프로세스를 자체 기준선과 비교해 측정합니다.

    추정치
  2. 02

    지금 사용 가능

    어떤 에이전트가 비용만큼의 값을 하나요?

    각 Mac에서 Fabric Dashboards는 에이전트마다 오늘, 7일, 30일 동안 쓴 금액을 모델별로, 자체 예산과 비교해 보여 줍니다. 수치는 에이전트가 직접 내는 사용 보고서에서 나오며, 아무도 모르는 비용은 US$0이 아니라 ‘알 수 없음’으로 표시됩니다. Switchboard는 Claude Code나 Codex 계정마다 사용 한도를 얼마나 썼는지, 언제 초기화되는지 보여 주므로 구독을 사용량 기준으로 과금되는 호출과 따로 볼 수 있습니다. Observatory는 각 프로젝트에서 무엇이 바뀌었는지 증거와 함께 보여 줍니다.

    Fabric Dashboards
  3. 03

    방향

    무엇이 가장 잘 작동하고, 어떻게 나머지로 넓힐 수 있나요?

    프로젝트와 워크플로별로 합친 지출과 결과. 재무가 한 번 정해 기록으로 남기고, 에이전트가 지출 전에 그 기록을 확인하는 한도. 한도를 넘는 요청은 기록으로 남고, 그동안에도 작업은 계속됩니다. 잘 작동하는 구성은 역할별 업무 공간으로 확대 적용합니다.

    추정치와 문의

에이전트와 워크플로에 관한 것이며, 사람의 순위를 매기지 않습니다.

03 / 추정치

추정치는 직접 확인할 수 있는
산수입니다

팀이 매달 이 프로세스에 쓰는 시간에, 에이전트가 현실적으로 맡을 수 있는 비율과 한 시간의 비용을 곱한 값입니다.

주당 시간 × 4.33×에이전트 담당 비율×간접비 포함 시간당 비용

현재 업무 방식별로 에이전트가 맡을 수 있는 비율
현재 방식비율
대부분 수작업25–50%
스크립트와 연동20–40%
채팅 어시스턴트를 필요할 때만 사용15–35%
일부를 이미 에이전트가 처리10–25%

예시: 대부분 수작업인 업무가 주 40시간이고 시간당 US$50이라면 월 173시간입니다. 에이전트가 그중 25–50%를 맡으면 월 43–87시간, 즉 월 US$2,150–4,350입니다.

약속이 아니라 추정치입니다. 무엇이든 확대 적용하기 전에 파일럿에서 실제 수치를 자체 기준선과 비교해 측정합니다.

04 / 요청

에이전트가 해 주었으면 하는 일을
알려 주세요

짧은 방법이 두 가지 있습니다. 코딩 에이전트가 몇 가지를 묻고 동의하시면 요청을 보내거나, 직접 몇 줄 적어 보내셔도 됩니다. 영업일 기준 2일 이내에 답변드립니다.

코딩 에이전트에게 맡기기

이 프롬프트를 Claude Code, Codex 또는 다른 코딩 에이전트에 붙여 넣으세요. 에이전트가 한 번에 하나씩 몇 가지를 묻고, 요청 내용을 보여 준 뒤, 동의하셔야만 보냅니다.

PassionCode.ai에 요청을 보내도록 도와줘. PassionCode.ai는 조직의 컴퓨터에 AI 에이전트를 도입하고, 각 에이전트에 얼마가 들었고 무엇을 해냈는지 보여 줘. 내 언어로 말해 줘. 아래 질문을 한 번에 하나씩 묻고 답을 기다려 줘. 처음 네 개는 건너뛸 수도 있어.

  1. 우리 조직에는 몇 명이 일하나요?
  2. 지금 어떤 AI 에이전트와 도구를 쓰고 있나요?
  3. 가장 원하는 것은 무엇인가요: 에이전트의 비용과 성과 보기, 반복 업무 자동화, 우리 프로세스용 에이전트 구축, 기존 에이전트나 프로젝트를 맞추기, 상용 라이선스, PassionCode.ai가 호스팅하고 운영, 또는 팀 온보딩과 교육?
  4. 언제 시작하고 싶나요?
  5. 몇 문장으로, 에이전트가 우리를 위해 무엇을 해야 하나요?
  6. PassionCode.ai가 어느 업무용 이메일로 답하면 되나요?

이 컴퓨터의 설정(예: 어떤 에이전트와 도구가 설치되어 있는지)은 먼저 나에게 묻고 내가 동의할 때만 봐 줘. 요청에는 코드, 비밀 값, 키, 파일 경로, 고객 데이터, 다른 회사나 사람의 이름을 절대 넣지 말고, 일은 일반적인 말로 설명해 줘.

그다음 요청을 JSON으로 작성해 줘. 키는 보이는 그대로 두고, 내 답에 맞는 나열된 값만 쓰고, 내가 건너뛴 항목은 빼 줘:

{
  "id": "a new random UUID v4: make it once, reuse it if you send again",
  "lang": "the language we talk in: en, ru, de, fr, es, pt-br, pl, ko, ja or zh-hans",
  "contact": {
    "email": "the work email",
    "message": "what agents should do, in my words, up to 4000 characters"
  },
  "goals": ["one of: cost_and_results, automate_operations, custom_agents, convert_agents, commercial_license, managed_hosting, team_onboarding"],
  "company": { "size": "one of: 1_10, 11_50, 51_200, 201_1000, 1000_plus" },
  "processes": { "tools": ["any of: claude_code, codex, cursor, chatgpt, other_agents, none"] },
  "budget": { "timeline": "one of: asap, this_quarter, next_quarter, exploring" },
  "source": { "channel": "agent-prompt", "agent": "your own name, such as Claude Code or Codex" }
}

양식 토큰을 받고 4초 기다린 뒤, 토큰을 JSON에 “form_token”으로 넣어 request.json으로 저장하고 요청을 검사해 줘. 검사는 아무것도 저장하거나 보내지 않아:

curl -s https://passioncode.ai/api/leads/token
sleep 4
curl -s -X POST 'https://passioncode.ai/api/leads?dry_run=1' -H 'Content-Type: application/json' --data @request.json

응답에 “issues”가 있으면 나와 함께 고쳐 줘. “valid”라고 하면 최종 JSON을 보여 주고 “이걸 PassionCode.ai에 보낼까요?”라고 물어 줘. 내가 동의한 뒤에만, 한 번, 같은 파일로 보내 줘:

curl -s -X POST https://passioncode.ai/api/leads -H 'Content-Type: application/json' --data @request.json

응답을 알려 줘. “received” 또는 “duplicate”이면 도착한 거야. “id”를 알려 주면 확인 메일이 뒤따라 와. 다른 응답이면 그 “message”를 보여 주고 더는 아무것도 보내지 마. 요청에 아무 응답도 없었을 때만 같은 파일로 한 번 더 시도하고, 새 “id”로는 절대 보내지 마. PassionCode.ai가 요청을 보관하는 방식: https://passioncode.ai/ko/privacy/

에이전트가 직접 가져갈 수 있는 일반 텍스트 버전: passioncode.ai/ko/business/agent-request.txt

05 / 질문

문의 전에

비용은 얼마인가요?

도구는 무료이며 오픈 소스입니다. 비용은 저희가 해 드리는 작업(프로세스 정리, 구축, 호스팅, 지원)과, 필요한 경우 상용 라이선스에 대해서만 발생합니다. 가격은 프로세스를 파악한 뒤 제안서에 명시하며, 정해진 패키지는 없습니다.

상용 라이선스는 언제 필요한가요?

도구는 GNU AGPL-3.0을 따릅니다. 내부 사용과 같은 라이선스로 공개하는 변경 사항에는 아무것도 필요하지 않습니다. 도구를 포함한 비공개 제품이나, 소스를 공개하지 않는 수정된 호스팅 서비스에는 상용 라이선스가 필요합니다.

사람을 감시하는 도구인가요?

아닙니다. 분석은 에이전트와 워크플로에 관한 것입니다. 각 에이전트에 든 비용과 해낸 일을 다루며, 사람의 순위를 매기지 않습니다.
