AI research digest: agents that learn from their own edits

This week's research is about memory: agents that keep a record of what they changed and why do better on the next run. Five results, what each measured, and what we take from them for agents that run a company's work.

PassionCode.ai research desk

Self-Improvement Memory Enables Continual Recursive Self-Improvement

arXiv 2611.18856

When an optimizer keeps improving an agent's harness after the benchmark or the model changes, it does better if it remembers its past edits, not only the current harness.

  • The setting: continue a harness-optimization run across compatible benchmarks or policy models instead of starting over.
  • The memory groups edits by the recurring problem they addressed and keeps the rationale, the predicted outcome, the observed outcome and the evaluation context.
  • Across ten source runs in coding, continuing with this memory beat continuing from the harness alone by 2.36 points on average (p = 0.003).

What we can adopt: Write the expected effect of a change before making it, next to the measured effect after it. The gap between the two is what the next change learns from.

Do LLM Agents Still Need to Be Told How to Self-Improve?

arXiv 2611.23219

A frozen model, given a compute budget and tools to collect experience and edit text notes, improves itself without a loop designed for it.

  • No external improvement loop: the agent decides how to experiment within its budget.
  • Sufficiently capable models do improve under these conditions.
  • The notes they learn transfer to other benchmarks, including different game horizons, mechanics and 3D navigation.

What we can adopt: Give an agent a fixed budget and a place to keep its own notes, then measure the notes on tasks it did not train on before trusting them.

Coding Agent Memory Post-Training II: file operations as long-horizon memory

arXiv 2611.14009

A small coding model can be trained to use ordinary files as its memory across context resets.

  • The environments give the policy plain Bash and a workspace that persists through the episode, so it can write, revise, search and reuse files when its context is replaced.
  • One policy is trained across five environments by on-policy distillation from a frozen teacher that already uses files well.
  • It gets 2.97 times the gain of the strongest distillation baseline on 640 test tasks; the 4B model gains 6.9 points on Terminal-Bench 2.1 and on SWE-Bench Pro V2.

What we can adopt: Test an agent's memory across a context reset, not only within one session: a handoff file that survives compaction is the behavior to measure.

The components of agent memory

Anthropic research

Anthropic describes dreaming: the agent reflects on its logs to fix mistakes and write new notes, and finds it a useful way to give a model effective memory.

  • Dreaming reorganizes memory from logs after the work, rather than during it.
  • In their tests, Claude Opus 5 was the first model to close the learning loop with memory on a long-horizon database task.
  • An earlier run shows the failure mode: a model wrote 413 memory files across 225 folders and earned one badge in a game.

What we can adopt: Schedule a daily review that reads yesterday's logs and rewrites the notes, and count notes that get used, not notes that get written.

An external sandbox for agent code

Simon Willison's weblog

The agent stays outside the sandbox and only the code it runs goes in, with three server implementations sharing one localhost API.

  • The sandboxes can route traffic through an HTTP and HTTPS allow-list proxy, so you decide which hosts the agent's code may reach.
  • The pattern keeps the agent's own keys and tools out of the environment where untrusted code runs.

What we can adopt: Run code an agent writes in a separate sandbox with an allow-list of hosts, and keep the agent's keys on the other side.

What we can adopt

  • Record the predicted effect of every change to an agent next to the measured one.
  • Measure an agent's memory across a context reset, with the handoff file it writes.
  • Run a daily review that turns logs into better notes, and track which notes get used.
  • Keep code an agent runs in a sandbox with an allow-list, apart from its keys.
