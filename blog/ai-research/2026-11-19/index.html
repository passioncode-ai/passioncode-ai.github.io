AI research digest · November 19, 2026

Memory Needs Checks, Harnesses Need Gates

This selection treats agent improvement as an evaluation problem. Procedural memory needs expectation checks and utility-based pruning, harness changes need retention gates, and self-improvement results need randomized task order. New training and benchmark results add evidence on asynchronous RL, trajectory efficiency, autonomous AI development, and judge calibration.

PassionCode.ai research desk

AdMem: Expectation-Grounded Procedural Memory

arXiv 2611.20605

AdMem turns expectation checks into utility-ranked procedural memories without requiring an environment reward.

  • Before each action, the actor commits to an expected outcome, while a concurrent critic compares the realized outcome and writes a binary reward and reflection.
  • A scalar utility updated online under a noisy-OR reward model ranks retrieval with context similarity and controls eviction and merging.
  • Across 707 tasks in eight AgentBoard domains, AdMem solved 441 tasks, versus 388 for ReAct and 312 for workflow induction.
  • Workflow-induction memory underperformed memoryless ReAct in seven of eight domains, and an unstructured per-step store lost half of ReAct's completions on Jericho.

What we can adopt: When building an agent memory, write entries only after an expectation check, rank them by utility and context similarity, and add utility-based eviction and merging.

Harness-Level Forgetting

dair.ai Academy

Updating any harness component can break previously reliable behavior while leaving the model untouched.

  • The paper names this failure harness-level forgetting and provides a measurement protocol.
  • A Continual Optimizer proposes candidate harnesses from post-execution feedback, and a Continual Evaluator commits only after checking current improvement, historical retention, and validity.
  • Experiments on textual reasoning, multimodal perception, and open-world interaction show capability accumulation and failure recovery, with relative gains exceeding 10% over corresponding baselines in multiple settings.

What we can adopt: Gate every harness change with an evaluator that checks historical retention alongside current improvement and validity before commit.

The Fragility of Self-Improving Agents

dair.ai Academy

Noisy multi-step evaluation and hidden task curricula can make self-improvement results fragile.

  • Agent evaluation is inherently noisy in complex environments and on multi-step tasks, and a self-improving loop can amplify that noise.
  • Improvement depends heavily on task order, and prior work often uses default orderings that impose an implicit curriculum.
  • Detailed rubrics and environment feedback in memory construction partially close the performance degradation, but significant gaps remain.

What we can adopt: Shuffle task order before measuring a memory loop, and test detailed rubrics plus environment feedback as memory inputs rather than assuming they remove degradation.

FlashREINFORCE: Single-Rollout Asynchronous RL

arXiv 2611.18627

FlashREINFORCE combines critic-free, single-rollout asynchronous training with controls for policy drift and negative updates.

  • One-Batch REINFORCE, a Sequence Trust Region, and Sample-Mean Optimization provide prompt coverage and batch centering while controlling policy drift and length-amplified negative updates.
  • Training remained stable through 6,000 updates on DeepSeek-R1-Distill-Qwen-1.5B at policy lag four, and through 1,450 updates on Qwen3-30B-A3B at lag eight.
  • With half the rollouts, it scored 38.0 versus 36.3 for published synchronous baselines on the Qwen2.5-Math-1.5B five-benchmark mean.
  • On Qwen2.5-7B-Instruct it maintained tool use where GRPO stopped calling tools and reached 98.3% seen and 96.5% unseen ALFWorld success.

What we can adopt: For asynchronous agent RL, evaluate single-rollout training with explicit drift and negative-update controls, and track tool calling alongside task success.

Singularity-Bench: Can Agents Build Agents?

arXiv 2611.16591

Singularity-Bench evaluates autonomous AI development across six end-to-end tasks and exposes reward hacking in the execution framework.

  • The tasks span pre-training, mid-training, post-training, inference, the agent harness, and cluster orchestration.
  • Red-teaming covered 9 of the 10 categories in the OWASP Top 10 for Agentic Applications, exposed reward-hacking vulnerabilities in Harbor, and led to Breakwater.
  • Opus 5.5 with Claude Code matched or outperformed the human baseline on all six tasks with a Singularity-Index of 1.25, while the remaining agents averaged 0.58.

What we can adopt: Use end-to-end agent-building tasks to evaluate autonomous development, and red-team the execution framework for reward hacking before trusting scores.

DetourBench: Exact Minimum-Action Bounds

arXiv 2611.20844

DetourBench makes trajectory efficiency measurable by computing exact minimum action counts for partially observable tasks.

  • Each task is a finite, partially observable transition system with unit-cost accesses whose resources become globally addressable after discovery, allowing exhaustive search to compute the exact minimum action count.
  • Across 375 scored episodes from five model endpoints on 25 integrated tasks with three repeats, success ranged from 58.7% to 96.0%.

What we can adopt: Benchmark interactive agents with both success and distance from an exact minimum-action bound so efficient trajectories are distinguishable from successful detours.

ReproBridge and AutoRefine

dair.ai Academy

Refined reproduction artifacts and calibrated judges improve both paper reproduction and agreement with deployed agent outcomes.

  • On 1,029 tasks from 36 papers, refined artifacts in ReproBridge raised reproduction success from 76.4% to 92.6% across four models and cut API spending by 19.7%.
  • On Meta's deployed performance-optimization agent, AutoRefine judge calibration raised agreement between the judge and real outcomes from 0.16 to 0.51.

What we can adopt: Refine reproduction artifacts before execution and calibrate agent judges against real outcomes before using their scores for optimization.

What we can adopt

  • Store procedural memories only after expectation checks, with utility-based retrieval and eviction.
  • Gate harness changes on current improvement, historical retention, and validity.
  • Shuffle task order before evaluating memory or self-improvement loops.
  • Evaluate agents on trajectory efficiency, tool use, and reward hacking, not success alone.
  • Calibrate automated judges against real outcomes.
